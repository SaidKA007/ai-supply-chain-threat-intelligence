# Week 6: запуск и загрузка на GitHub

## Что сделано

Эта неделя продолжает тему обработки моделей из Week 4 и Week 5. Мы проверяем один конкретный механизм: при загрузке специально подготовленного учебного объекта вызывается Python-функция. Вместо вредного действия она создаёт обычный текстовый файл.

В основном README и материалах для GitHub используется английский. Этот файл — инструкция для запуска.

## 1. Положи папку в проект

Распакуй архив и скопируй **всю папку `week6`** в корень своего локального репозитория, рядом с `week1`, `week2`, `week3`, `week4` и `week5`. Не создавай вложенность `week6/week6` и не заменяй корневой README файлом из шестой недели.

## 2. Запусти из корня репозитория

Открой проект в VS Code и его терминал:

```bash
python --version
python week6/simulation/run_lab.py
```

Нужен Python 3.10 или новее. Установка библиотек не требуется. В Windows вместо `python` можно использовать установленный лаунчер `py -3`; в Kali обычно используется `python3`.

Программа создаст новую папку внутри `week6/runs/` и напечатает её путь. Она не перезаписывает предыдущий результат. `evidence/reference_run/` — отдельный проверочный запуск, выполненный при подготовке пакета в среде ассистента, а не на твоём компьютере.

## 3. Разбери четыре результата

| Сценарий | Что должно получиться | Что это показывает |
|---|---|---|
| S01 | `loaded`, маркера нет | Обычное восстановление учебных данных. |
| S02 | `loaded`, маркер есть | Функция выполнилась во время загрузки. |
| S03 | `load_error`, маркер есть | Функция успела выполниться до ошибки. |
| S04 | `pickle_blocked_json_loaded`, маркера нет | Запрещённый формат не передавался загрузчику Pickle; отдельные JSON-данные приняты. |

**Ошибка S03 запланирована.** Поэтому одновременно увидеть `load_error` и `PASS` нормально: именно это поведение проверяет сценарий.

В папке нового запуска открой `results.csv`, `console.txt`, `events.jsonl`, а затем `markers/S02.txt` и `markers/S03.txt`. `callback_count` — сколько раз сработала учебная функция; `marker_exists` — существует ли созданный ею файл. Два маркера не означают две реальные атаки.

Запуск не скачивает модели, не открывает обратную оболочку и не подключается к чужим адресам. Не меняй его на загрузку неизвестных файлов.

## 4. Проверь тесты

```bash
python -m unittest discover -s week6/tests -v
```

Ожидаются `Ran 15 tests` и `OK`. Это проверки поведения программы, а не оценка качества обнаружения атак.

## 5. Открой Navigator

Ссылка на официальный Navigator есть в разделе 8 [основного README](../README.md). Создай новую вкладку, открой **Open Existing Layer**, выбери **Upload from local** и укажи `week6/navigator/week6_layer.json`. Подсвечена одна подтехника: **T1059.006**, тактика **Execution**.

Слой подготовлен как JSON. Скриншот его импорта нужно делать после собственного открытия: в пакете нет выдуманного изображения интерфейса.

## 6. Какие скриншоты подходят для собственной демонстрации

Достаточно показать результат выполнения четырёх сценариев в терминале, содержимое маркера S03 вместе с его ошибкой в таблице результатов, а также импортированный слой Navigator. Эти изображения должны относиться к твоему реальному запуску. Для одной только загрузки готовых материалов на GitHub новые скриншоты не обязательны, если преподаватель отдельно их не требует.

Собственные результаты по умолчанию находятся в игнорируемой Git папке `runs/`. Чтобы сохранить выбранный запуск в репозитории, скопируй только его нужные файлы в новую подпапку `week6/evidence/student_run/` и укажи в README, где и когда они получены. Не заменяй проверочный запуск без обновления его описания.

## 7. Загрузи на GitHub

Через сайт: открой корень репозитория, выбери **Add file**, затем **Upload files** и перетащи папку `week6`, сохранив подпапки. Проверь, что загружается не только README.

Через Git из локального репозитория:

```bash
git status
git add week6
git commit -m "feat(week6): add benign Python ATT&CK simulation and evidence"
git push origin main
```

Команда `push` предполагает твою текущую ветку `main`. Не добавляй `--force`. Обновление таблицы на главной странице описано отдельно в [root_readme_update.md](root_readme_update.md).
