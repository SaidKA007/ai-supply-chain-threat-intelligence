# Что сделать сегодня

**Цель первого коммита:** зафиксировать исследовательский вопрос, честный обзор литературы и рабочий сбор метаданных. Сегодня не нужно обучать 40 моделей или искать трояны в 300 репозиториях.

## 1. Создай отдельный репозиторий

Название: `hf-model-screening-study`.

Распакуй стартовый архив. В корне должны находиться `README.md`, `requirements.txt`, `docs/`, `scripts/`, `tests/`, `data/` и `results/`. Документы написаны на английском для репозитория; этот файл объясняет действия по-русски.

## 2. Прочитай и зафиксируй постановку

Основной вопрос: **при одинаковом числе тестов какой способ поведенческой проверки лучше выявляет однословные и составные бэкдоры, если точный триггер проверяющему неизвестен?**

Открой `docs/literature_matrix.md` и `docs/protocol.md`. Планируемый вклад — сравнительный эксперимент с ограниченными ресурсами, а не утверждение, что раньше никто не сканировал модели. Глобальная новизна ещё не доказана.

## 3. Проверь код и собери маленький инвентарь

В терминале VS Code, открытом в папке проекта, выполни:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/collect_metadata.py --limit 10
```

Если `py` не найден, используй `python` в первой команде. Активация окружения не требуется.

Скрипт обращается к публичному API, фиксирует commit SHA и сохраняет названия файлов и метаданные. Он не скачивает веса, не запускает модели и не делает выводов о заражении. Если сеть недоступна, сохрани настоящий журнал ошибки; не называй пустой результат успешно собранной выборкой.

В подготовленном архиве проверены 8 автономных тестов. Живой сбор здесь не выполнен: в среде подготовки не разрешилось доменное имя. Поэтому исходные данные сегодня получатся только после твоего успешного запуска.

## 4. Выложи первый результат на GitHub

Через интерфейс GitHub: создай репозиторий → `Add file` → `Upload files` → загрузи файлы проекта и фактически полученную папку `data/metadata_...`.

**Не загружай `.venv`, `__pycache__`, токены, файлы весов и PDF статей.** При загрузке через браузер `.gitignore` не отфильтрует их за тебя.

Сообщение коммита:

```text
Add literature review, screening protocol and metadata pilot
```

Если сбор не удался, не пиши `metadata pilot completed`. Подходящее сообщение:

```text
Add literature review, screening protocol and tested metadata collector
```

## Что должно быть готово к концу сегодняшнего этапа

1. Обзор всех 20 статей и исправленная формулировка исследовательской задачи.
2. Явный протокол: контрольные модели, неизвестные триггеры, равный бюджет, отдельные метрики.
3. Работающий на автономных тестах коллектор; при успешном доступе к сети — реальный маленький инвентарь и журнал запуска.
4. Репозиторий со статусом `research design / metadata pilot`, а не вымышленными результатами поиска бэкдоров.

**Следующий экспериментальный этап:** одна контролируемая пара «чистая / с известным учебным бэкдором» и проверка её поведения. Именно размеченный поведенческий эксперимент, а не количество собранных репозиториев, отвечает на основной вопрос.
